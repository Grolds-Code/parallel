# Public offline verification lab

`public_demo.py` defines **parallel-public-demo**, a separate CPU-only public
ASGI application targeting **Modal Python SDK 1.6.3**. It does not change or import
`app.py`, the authenticated `parallel-llama` GPU service. No deployment has been
performed as part of this change.

The existing development command remains:

```sh
uv run --offline python -m parallel_agent.web_demo
```

It still binds only to `127.0.0.1:8765`. The shared interface now describes
recomputation as offline, whether hosted locally or on Modal.

## Public contract

Only `GET` and `HEAD` are supported:

| Path | Accepted query | Result |
| --- | --- | --- |
| `/` | none, or the referral fields described below | Existing `index.html`, unchanged |
| `/app.js` | none | Existing JavaScript |
| `/style.css` | none | Existing stylesheet |
| `/api/evidence` | none, or exactly `scenario=delete`, `scenario=replacement`, `scenario=create` | Fresh deterministic offline evidence |

The homepage alone accepts the literal, case-sensitive keys `utm_source`,
`utm_medium`, `utm_campaign`, `utm_term`, and `utm_content`. For example,
`/?utm_source=chatgpt.com` returns the same HTML and security headers as `/`.
Each key may occur at most once, with a nonempty value of 1–128 ASCII characters
from `A-Z`, `a-z`, `0-9`, `.`, `_`, `~`, and `-`. Fields are separated by a single
`&` and each uses exactly one `=`. Values are ignored and never reflected into
HTML. Percent encoding, plus signs, whitespace, empty fields, extra separators,
unknown keys, and duplicate keys (even with identical values) are rejected.

Referral fields are not accepted on assets, the evidence API, or other paths.
The evidence API still accepts only the exact query bytes listed in the table,
with no defaults except omitted scenario (deletion). Blank/unknown scenarios,
encoded aliases, and additional fields remain rejected. Noncanonical paths are
rejected. Target limits are 128 path bytes, 1024 query bytes on `/` only, and
64 query bytes everywhere else. Oversized targets return 414; invalid queries
on known paths return 400. Bodies and streaming uploads are rejected without buffering/draining;
waiting for an initial empty ASGI request event is limited to one second.
All other HTTP methods return 405; WebSockets are denied. There are no docs,
file mounts, directory listings, inference proxy, user proposals, execution,
search-budget inputs, writes, cookies or cross-origin API grants.

The three synthetic proposals use `web_demo.build_evidence` and the real
`simulate`, `verify`, `evaluate`, bounded search and repair engine. Search is
fixed at 3 states per comparison/iteration, 6 total in the repair loop and one
fixed local repair callback. The initial snapshot is reconstructed for every
request. No model response is generated. The 63.73-second Meta Llama result is
labeled **historical live run**; all recomputations remain **OFFLINE REPLAY**.
Bounded evidence is not universal safety or execution approval.

Unexpected exceptions and internal action/goal/repair errors return a generic
failure with no verdict or exception details. Application responses include
no-store, nosniff, a restrictive CSP, frame denial, no-referrer, restricted
permissions, same-origin resource policy and HSTS. No request logging is added.
Headers and errors generated by Modal's proxy are outside this application's
control and require a future live check.

## Isolation and limits

- No GPU; CPU request/limit **0.25/0.5 cores**, memory request/limit **256/512 MiB**.
- Minimum 0, maximum 1, buffer 0 containers; 10-second idle scale-down.
- One concurrent input; 15-second function timeout and 60-second startup timeout.
- Outbound network blocked and Modal resource access restricted on the function.
- No attached secrets, proxy credentials, inference token, volumes or HF cache.
- No dependency on vLLM, Transformers, Hugging Face or a model download.
- Explicit source/asset file manifest, automatic source inclusion disabled.
  Neither the repository root nor local environment/configuration is uploaded.
  `llm.py` is included solely because the existing package initializer exports its
  inert classes; the public app never constructs a connector or reads its config.

The manifest includes the deployment module at its importable container path.
The image only sets a fixed `PYTHONPATH`; it does not forward local environment
variables. Modal-managed runtime infrastructure is distinct from user-attached
secrets. The application performs no filesystem writes; the container itself is
not claimed to be a read-only filesystem or a general Python sandbox.

## Offline validation

From the repository root:

```sh
uv run --offline pytest -q
node --check src/parallel_agent/web_assets/app.js
node --check tests/web_demo_ui.cjs
git diff --check
```

`tests/test_public_demo.py` calls ASGI directly with network/model entry points
blocked. It covers assets, evidence, deterministic engine results, validation,
methods, bodies, traversal, errors, headers, lifecycle and WebSocket rejection.
Referral regressions cover the ChatGPT URL, unchanged HTML and HEAD responses,
value/target limits, malformed and duplicate fields, and API query injection.
`tests/test_public_modal_deployment.py` captures the entire declaration with a
fake SDK and checks the file manifest and resource/security configuration.
Existing local server, UI harness, engine and GPU deployment tests remain intact.

Use a separate SDK environment; do not add Modal to project dependencies:

```sh
uv venv /tmp/parallel-public-modal-venv
uv pip install --python /tmp/parallel-public-modal-venv/bin/python -r deployment/modal/requirements.txt
/tmp/parallel-public-modal-venv/bin/python deployment/modal/check_public_import.py
```

The install may download packages; with a populated uv cache, add `--offline`
to `uv pip install`. The check itself uses the real **1.6.3** SDK, prohibits
socket connections, DNS, listening sockets and subprocess launches via a Python
audit hook, imports the deployment and calls only the local ASGI factory. It
needs no cloud credentials and does not build an image or hydrate resources.
This check was successfully run using the already cached 1.6.3 environment.

## Proposed deployment (operator action; not run)

After reviewing the change, use the separate environment above and an already
authenticated Modal workspace. From the repository root, select the intended
existing Modal environment explicitly (replace `main` if needed):

```sh
/tmp/parallel-public-modal-venv/bin/modal deploy --env main deployment/modal/public_demo.py
```

This creates a public endpoint; use the HTTPS URL printed by Modal. Do not run
`deployment/modal/app.py`, prefetch weights, add secrets, or attach the inference
service's proxy token/cache to this app. Account credentials used by the local
CLI are not application secrets to attach to containers.

A future authorized live check must verify image startup, explicit source
packaging, proxy routing, headers, body/method rejection, resource restrictions,
scale-to-zero and billing. Offline import does not prove those cloud properties.
Timeouts do not establish an end-to-end queue/cold-start deadline. Public traffic
can queue or keep the sole container busy; no application rate limiter or total
spend cap is claimed.

## Rollback / shutdown (operator action; not run)

For the first deployment, remove public availability by stopping only this app:

```sh
/tmp/parallel-public-modal-venv/bin/modal app stop --env main parallel-public-demo
/tmp/parallel-public-modal-venv/bin/modal app list --env main
```

Confirm the app is stopped and no containers remain in the dashboard. There is
no public-demo volume/cache to delete. Do not stop `parallel-llama` or revoke its
credentials. For a later update with an existing prior deployment, restore the
previous public-demo version with:

```sh
/tmp/parallel-public-modal-venv/bin/modal app rollback --env main parallel-public-demo
```

To select a known historical version, append its version, for example `v3`.
Rollback keeps the public endpoint deployed and can incur compute charges;
shutdown is the appropriate way to end the trial. Check residual billing.

## Approximate costs

Using the **illustrative rates already recorded in this repository**, not a
fresh pricing quote: $0.0000131/core-second and $0.00000222/GiB-second imply
about **$0.014 per active hour** at the requested 0.25 core/0.25 GiB, or
**$0.028 per active hour** at 0.5 core/0.5 GiB. That is roughly $0.00023–$0.00046
per active minute, or $10–$20 for 720 continuously active hours, for those
CPU/memory allocations alone. Actual billing rules/usage may differ; these are
not upper bounds on the bill. Builds, startup, idle scale-down time, network and
other account/platform charges may add cost. Verify current pricing before
deployment; no external pricing service was contacted for this preparation.

Scale-to-zero can reduce idle compute, but does **not** guarantee zero costs.
One container bounds parallelism, not monthly spend or abuse. No free credits
are assumed. Monitor account usage and stop the app when finished.
